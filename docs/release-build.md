# Сборка IPA без комментариев

Комментарии остаются в исходниках, а в IPA их нет.

Комментарии в Swift, Objective-C и C в IPA не попадают никогда: компилятор отбрасывает их
при сборке, и в приложении остаётся только машинный код. Удалять их из исходников перед
сборкой бессмысленно — IPA от этого не изменится ни на байт.

Комментарии попадают в IPA только вместе с кодом, который приложение везёт как текст и
читает заново на устройстве. Такой код очищается при каждой сборке:

- **Прелюдия плагинов.** Это JavaScript внутри строки Swift: он лежит в бинарнике байт в
  байт и разбирается при запуске каждого плагина. Перед компиляцией из собираемой копии
  убираются комментарии, пустые строки и отступы. Прелюдия становится примерно на треть
  меньше: около 188 КБ → 125 КБ. Очищенная прелюдия обязана быть той же программой: те же
  токены, те же проверки Node, что в предварительной проверке прелюдии, и та же строка,
  которую из неё собирает Swift. Иначе сборка останавливается.
- **Ресурсы в готовом IPA.** У JavaScript, CSS и HTML режима чтения, встроенных видео и
  HLS-плеера, а также у текстовых таблиц `.strings` убираются комментарии. Уведомления о
  лицензии и авторских правах остаются: сторонний код можно распространять только с ними.
  Очищенный скрипт должен разбираться Node и состоять из тех же токенов, что и исходный.
  Файл, который нельзя прочитать с полной уверенностью, попадает в IPA без изменений.

После очистки весь IPA проверяется: в нём ищутся фразы, которые в исходниках AorusGram и в
прелюдии являются комментариями. Найденная фраза останавливает сборку. Это одновременно
показывает, что компилятор отбросил комментарии Swift, а очистка перед сборкой — комментарии
прелюдии.

Очистку выполняет `scripts/strip_shipped_comments.py`: шаг `prelude` — перед сборкой, шаг
`ipa` — после упаковки, до проверки IPA.
