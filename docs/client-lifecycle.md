# Запуск, фон и возвращение в клиент

## Стартовая поверхность

`LaunchScreen.xib` использует непрозрачный чёрный фон независимо от системного
оформления. После создания окна тот же цвет установлен у окна и контейнера
`Window1`. Окно становится видимым до операций, которые могут завершить запуск
ранним возвратом. Когда готова `PresentationData`, контейнер получает цвет темы
аккаунта. Цвет стартовой поверхности не меняет сохранённую тему чатов и настроек.

Подстановка строк подключена в `getSingle` генератора PresentationStrings.
Сохранённая таблица читается один раз; последующие обращения читают словарь
под короткой блокировкой. Обновление словаря не выполняет файловые операции
внутри блокировки и не ждёт главной очереди.

## Работа при возвращении из фона

| Компонент | Выполняемая работа | Очередь |
|---|---|---|
| Менеджер плагинов | Чтение манифестов, исходников и разрешений, хеширование и анализ вызовов API | Последовательная очередь `aorusgram.pluginReload` |
| Менеджер плагинов | Проверка поколения снимка, запуск отсутствующих плагинов и публикация интерфейса | Главная |
| HUD | Чтение CPU, памяти, сети и свободного места | Отдельная последовательная очередь замеров |
| HUD | Состояние батареи, FPS, привязка к окну и отрисовка | Главная |
| Транспорт | Проверка и восстановление ядра туннеля | Очередь менеджера транспорта |
| Удалённые сообщения | Регистрация фонового задания; SQLite и обслуживание WAL | SQLite на очереди кэша |
| Защита снимков | Проверка цепочки защищённых слоёв и текущего корневого окна | Главная |
| Анимированные фоны | Возобновление проигрывателя; обработка и конвертация медиа | Интерфейс на главной, конвертация в фоне |

Чтение плагинов не задерживает кадры интерфейса. Каждому запросу соответствует
номер: результат предыдущего запроса не применяется после нового. Изменение
поколения хранилища во время чтения требует нового снимка. Защищённые файлы
читаются после доступности данных устройства. Уже работающий плагин сохраняет
свои таймеры, соединения и состояние при обычном возвращении в приложение.

У HUD одновременно выполняется один замер. Его результат относится к конкретному
поколению окна; закрытие или замена окна отменяет применение старого результата.
В фоне таймер и display link остановлены, а предыдущая скорость сети сброшена.
`task_threads` возвращает массив и права на каждый порт потока. Обе реализации
HUD освобождают каждое право через `mach_port_deallocate`, а память массива —
через `vm_deallocate` после каждого замера.

## Иконки

Системные символы сначала получают размер и вес, затем растеризуются с масштабом
экрана и проходят обработчик оформления. Монохромный bitmap остаётся template,
поэтому цвет задаёт элемент интерфейса. Явная палитра цветного символа сохраняется.
Конфигурация, применённая после загрузки символа, обрабатывает его исходный вектор.

SwiftUI-панель форматирования использует тот же обработчик, что и нативная кнопка
диктовки. Изменение оформления обновляет наблюдаемое поколение иконок. При
предупреждении о памяти временные изображения удаляются из кэша без изменения
темы; при следующем обращении они создаются снова.

## Проверки

`scripts/client_lifecycle_check.py` проверяет стартовые цвета, фоновые чтения,
отбрасывание устаревших снимков и результатов HUD. Цепочка загрузки значков
проверяется на внедрённых файлах: отсутствие помощника SwiftUI или обход
обработчика в любой её точке останавливает проверку. На macOS выполняются
1200 замеров CPU для каждой реализации с проверкой отсутствия роста числа прав
на порт текущего потока. `scripts/plugin_icons_check.py` проверяет обработчик
bitmap и запускает тесты UIKit на симуляторе, включая цвет, размер и конфигурацию.

Для воспроизведения зависания на устройстве следует записать вход и выход из фона
в Instruments: Time Profiler для нагрузки на главный поток, System Trace для
ожиданий и Allocations для роста памяти. Проверяются обычный вход, возвращение
через 20 минут, повторные быстрые переключения и пересоздание процесса системой.
Запись на устройстве нужна для установления причины конкретного зависания:
проверки компонентов не воспроизводят планирование iOS после длительной приостановки.
