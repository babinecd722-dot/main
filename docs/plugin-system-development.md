# Сборка и проверка системного API плагинов

Слой Telegram API закреплён переменной `TELEGRAM_IOS_COMMIT` в
`.github/workflows/build-aorusgram.yml`. Мост плагинов генерируется из исходников этого
слоя, поэтому имена, типы, флаги и TL ID соответствуют собираемому клиенту.
`AorusPluginTL.generated.swift` создаётся при сборке и не хранится в репозитории.

## Генерация

```sh
python3 scripts/gen_plugin_tl.py \
    /path/to/Telegram-iOS/submodules/TelegramApi/Sources \
    /path/to/Telegram-iOS/submodules/TelegramApi/Sources/AorusPluginTL.generated.swift
```

В тот же каталог копируется `patches/submodules/TelegramApi/Sources/AorusPluginTL.swift`.
Оба файла компилируются в TelegramApi. Генератор вызывает штатные функции и конструкторы;
собственного сериализатора плагинов нет. Проверка двоичных границ использует описания
этого же слоя до вызова штатного парсера.

Генератор сверяет методы с FunctionDescription, а конструкторы — с таблицей парсеров
Telegram. Неизвестная форма объявления или неполный каталог прерывают сборку.
При изменении структуры исходников Telegram следует обновить генератор.

## Строки интерфейса

Названия и описания разрешений в `AorusPluginControllers.swift` используют
`aorusL(ru, en)`. Русский и английский тексты задаются в месте вызова, остальные
языки — в `AorusL10nTable.swift`. Ключ каждой записи совпадает с английским текстом
целиком. При удалении строки удаляется её ключ; форматные подстановки сохраняются
в переводе.

```sh
python3 scripts/aorus_l10n_check.py .
python3 scripts/tests/test_aorus_l10n_check.py
```

Проверка читает строки экранов и патчей Telegram, сверяет ключи, повторения и
подстановки. Она выполняется до загрузки Telegram и повторно в проверке оформления
собранного дерева исходников.

## JavaScript

```sh
python3 scripts/plugin_prelude_check.py .
python3 scripts/plugin_system_prelude_check.py .
```

Первая проверка выполняет прелюдию и проверяет разрешения, события и существующий API.
Вторая проверяет MTProto, описание и пагинацию, ошибки RPC, отмену, последовательные
пакеты, сетевой профиль, двоичные HTTP-данные и все методы Files API. Host отвечает через тот же dispatcher,
который использует клиент; настоящий аккаунт не задействуется.

## TL и нативный транспорт

```sh
python3 scripts/plugin_tl_check.py . \
    /path/to/Telegram-iOS/submodules/TelegramApi/Sources \
    --export-api /tmp/aorus-plugin-api
python3 scripts/plugin_system_native_check.py . /tmp/aorus-plugin-api \
    --telegram-core-sources /path/to/Telegram-iOS/submodules/TelegramCore/Sources
```

Нужны Python 3, Node и Swift. Путь к Swift задаётся через `--swiftc`.
TL-проверка компилирует настоящий TelegramApi с мостом. Каждый конструктор проходит
проверку ID, кодирования, разбора и повторного кодирования; каждый RPC — подготовку
запроса и парсер результата. Необязательные поля проверяются по группам флагов.
Также проверяются неверные типы, большие целые, обрезанные ответы, лишние байты и векторы.

Нативная проверка использует собранный TelegramApi и управляемый транспорт вместо
соединения с Telegram. Проверяются аккаунт, передача Updates менеджеру состояния,
ошибки, deadline, отмена, повторное использование ID и лимит запросов.
Мост передачи Updates компилируется внутри TelegramCore; сигнатура и доступ
метода в тестовом заменителе сверяются с исходником закреплённой версии Telegram.
HTTP проверяется на локальном сервере: байты, потоковый лимит, перенаправления,
заголовки, отмена и файлы. Файловый API компилируется из исходника клиента;
проверяются создание, перезапись, квота, параллельное добавление, папки, Unicode-пути,
копирование, перемещение и двоичные порции. ZIP проверяется в обе стороны со стандартным
архиватором Python: сохранённые и Deflate-записи, пустые папки, контрольные суммы,
обрезанные данные и откат ошибочной распаковки.

На Linux адаптируется только тестовая копия Buffer.swift: Foundation иначе объявляет
NSMutableString и C-указатели. Исходники Telegram не изменяются.
Для WebSocket используются completion-формы Apple API или тестовый адаптер к
async-формам swift-corelibs.

Проверки не отправляют RPC на сервер Telegram. Сериализация не подтверждает серверные
права аккаунта, доступность метода или выполнение платежа.
Полная сборка iOS и проверки UIKit выполняются существующим workflow на macOS.

## Экспорт и иконки

```sh
python3 scripts/plugin_exports_check.py .
python3 scripts/plugin_icons_check.py .
python3 scripts/tests/test_swift_call_label_check.py
```

Экспорт справочника использует тот же текст, который показывается в клиенте.
Проверка компилирует настоящий форматтер и проверяет обе языковые версии,
Markdown-примеры, время UTC, уровни и многострочные записи консоли.

Пиксельная проверка компилирует функции отрисовки из Display. Набор изображений
проверяет связность контуров, отверстия, отдельные точки, цвета, прозрачность,
размер холста и повторяемость результата. На macOS обработчик иконок также
проверяется с iOS SDK и запускается в доступном iPhone-симуляторе: три загрузчика
SF Symbols, растеризация, размер, повторное применение стиля, замена голосового
ввода, превью и сброс стиля. Для этой части нужен установленный iOS Simulator.
Заменитель AppBundle передаёт только загрузку ресурсов; UIKit и Objective-C runtime
используются настоящие.

JavaScriptCore-проверка в workflow создаёт файл плагина, читает его метаданные,
импортирует его в отдельное хранилище и проверяет выключенное состояние.
Отправка документов использует штатную очередь Telegram. Проверки без аккаунта
подтверждают формирование запросов и разрешения, но не доставку документа на сервер.
