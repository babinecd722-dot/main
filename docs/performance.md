# Производительность

Места, где клиент повторял одну и ту же работу при каждой отрисовке или каждом разборе
данных, и что с ними сделано.

## Ответы AorusAI

Markdown-рендерер ответа компилировал регулярные выражения при каждом проходе, а проход
списков — по два выражения на каждую строку ответа. Ответ рендерится заново на каждый
пришедший кусок текста, поэтому во время печати это происходило много раз в секунду на
главном потоке. Теперь каждое выражение компилируется один раз и переиспользуется, так же
как выражения разбора формул. Форматтер дат в списке чатов AorusAI создаётся один раз.

## Фейковые подарки

Список подарков хранился как JSON и декодировался целиком при каждом обращении: проверка
«есть ли подарок», поиск по ключу, закрепление, ношение — для каждой ячейки и каждого
сообщения с подарком. Кроме того, каждый подарок при каждом обращении заново декодировал
свой `StarGift`, а поиск по ключу делал это для всех подарков подряд. Теперь список
декодируется один раз для каждого сохранённого значения, а каждый подарок — один раз для
своих данных.

## Обращения к связке ключей

Связка ключей — вызов в другой процесс. Персонализация премиума спрашивала её о статусе
и цветах для каждого пользователя, которого разбирает Telegram, при каждом обновлении,
хотя данные там есть только у своих аккаунтов. Теперь список записей читается один раз, и
у кого записи нет, туда не ходят. Переключатели и балансы фейковых подарков и звёзд у
тех, кто их ни разу не трогал, тоже ходили в связку ключей при каждой отрисовке; ответ
«не найдено» теперь запоминается до конца запуска. После загрузки настроек всё читается
заново.

## «Реальный онлайн»

Время последней активности хранилось отдельным ключом настроек на каждого собеседника.
За несколько недель в больших группах это тысячи ключей, а каждая запись в настройки
переписывает их все. Теперь это одна таблица: последние сутки и не больше 400 человек,
запись пачкой раз в пару секунд. Старые ключи один раз переносятся в таблицу в фоне и
удаляются.

## Стена

Папка просмотренных постов искалась, создавалась и помечалась заново для каждого
просмотренного поста; теперь один раз. После загрузки настроек кэши Стены сбрасываются,
чтобы отметка просмотра не записала старый список поверх загруженного.

## Переключатели AorusGram при запуске

Каждый переключатель AorusGram при изменении сохраняет всю таблицу настроек, копирует
флаги в ключи, которые читают патчи Telegram, применяет защиту от скриншотов и сообщает
всем экранам и плагинам, что настройки изменились. Чтение таблицы при запуске и при
загрузке настроек присваивало все пятьдесят переключателей подряд, и каждое присваивание
делало всё это заново: пятьдесят записей таблицы, около двух тысяч записей ключей,
пятьдесят включений и выключений защиты от скриншотов и пятьдесят перестроений открытых
экранов и событий в каждый плагин. Теперь, пока таблица читается, сохранение не
выполняется; при загрузке настроек после чтения выполняется одно. Так же устроены
настройки антиспуфа.

## Siri

Команды Siri заново регистрировались, а при выключенной функции система просила удалить
их все — при изменении любой настройки AorusGram, не только переключателя Siri. Теперь это
происходит только когда меняется сам переключатель.

## Бейджи DEV и кота

Картинка бейджа рисовалась заново при каждой раскладке каждой строки списка чатов и каждого
сообщения его владельца, а кот — уменьшением большой картинки. Теперь картинка одного
размера и цвета рисуется один раз. Значки вкладок плагинов тоже кэшируются с пределом,
чтобы смена тем не копила их без конца.

## Уведомления из транзакции базы

Проверка входящих сообщений работает внутри транзакции базы аккаунта, в его потоке. Оттуда
антиспам и автоответ отправляли уведомления, которые обрабатываются в главной очереди, а
такая отправка из другого потока ждёт, пока главный поток их обработает: транзакция стояла,
пока главный поток был занят анимацией или отрисовкой. Теперь эти уведомления передаются в
главную очередь асинхронно.

## Антиспам

Встроенные образцы спама при каждой проверке заново нормализовались — около трёхсот раз на
сообщение; теперь каждый один раз. Окна частоты сообщений по отправителям больше не копятся
за всю сессию. При запуске включение антиспама с тем же значением больше не переписывает всё
состояние в настройки и дважды в связку ключей на главном потоке. Время последнего
уведомления антиспама хранилось отдельным ключом на каждого отправителя и не удалялось; теперь
это одна таблица на последнюю минуту, а старые ключи удаляются один раз в фоне.

Стоп-слова проверяются при отрисовке сообщений, поэтому проверка сделана быстрой: текст
разбирается за один проход, ответ для одного и того же текста запоминается до изменения
списка, а без стоп-слов проверка не выполняется вообще.
